# ADR 0006: Password Authentication, Invite Registration & Picord Brand Identity

## Status
Accepted

## Context
1. **Brand Identity**: Picord was forked from the upstream `pi-pocket` prototype but has evolved into an independent, channel-first personal AI runtime. The original icon featured a traditional Greek letter `π` inside a square frame. To reflect its distinct identity, Picord requires a bespoke, modern brand icon centered on a high-tech "P" glyph and channel geometry that integrates with the dynamic theme palette system.
2. **Authentication Flow**: Previously, all logins relied solely on long-lived 32-character bearer tokens printed to terminal logs or shared via `/login?token=...` links. This presented significant UX barriers for mobile PWA users who cannot easily copy long tokens.
3. **User Registration & Security**: The existing invite system (`/join/:code`) allowed temporary short-lived invites (15m–1w), but lacked:
   - A unified username/password credential system.
   - A standard `/register` web form for invite redemption.
   - Password-protected access for administrator `John` and subsequent members.
   - Protection against automated bots if open registration were enabled.

## Decision
1. **Native `crypto.scrypt` Password Hashing**:
   - Implement `src/server/password.ts` using Node.js's built-in `crypto.scrypt(password, salt, 64, { N: 16384, r: 8, p: 1 })`.
   - Store password hashes in `config.json` as `passwordHash: "scrypt$<saltHex>$<derivedKeyHex>"`.
   - Zero external npm dependencies (avoiding native C++ build hurdles in minimal containers like InstaBox).
2. **Administrator Password Provisioning**:
   - Initialize administrator `John` with a secure scrypt password hash.
   - Maintain backward compatibility with the existing `ownerToken` for emergency recovery and machine-to-machine operations.
3. **Controlled Invite Registration**:
   - Web registration at `/register` strictly requires:
     - A valid, unexpired invite code generated by admin `John`.
     - A unique username.
     - A password conforming to length requirements.
   - Successfully redeeming an invite registers a new user (`role: "member"`), writes their password hash and personal token to `config.json`, and issues an authenticated `pocket_auth` session cookie.
4. **Card-Style Login & Registration UI**:
   - `/login`: Clean dark-themed login card (Username + Password) with links to `/register` and emergency token login.
   - `/register`: Structured registration card (Invite code + Username + Password + Confirm password).
5. **Picord Brand Icon**:
   - Redesign `web/icon.svg` and `web/app-icon.js` to feature a faceted geometric "P" glyph intertwined with channel matrix elements.
   - Retain dynamic theme color bindings (`--o-bg`, `--o-bg-darker`, `--o-cyan`, `--o-green`, `--o-orange`).
   - Regenerate PWA raster assets (`icon-192.png`, `icon-512.png`, `apple-touch-icon.png`).

## Consequences

### Positive
- **Streamlined Mobile Login**: Users log in on any device using familiar credentials (`John` + password) without hunting for URL tokens.
- **Controlled Onboarding**: Strict invite verification prevents unauthorized public abuse of LLM APIs and VPS resources.
- **Zero-Dependency Security**: Native `scrypt` avoids fragile C++ build environments while offering industry-standard memory-hard resistance to GPU cracking.
- **Distinctive Visual Brand**: Establishes Picord's unique identity across desktop browser tabs, mobile PWA home screens, and notifications.

### Negative / Trade-offs
- Users must remember or store their password.
- Admin must generate invite codes for any new member wanting to join.
