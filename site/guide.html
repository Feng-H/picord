第一部分 · 业务功能

这个项目是干什么的。

一句话:Picord 是一个装在你自己服务器上的「AI 工作台网站」。你用手机或电脑打开它,像用聊天软件一样跟一个叫 Pi 的 AI 助手说话;它不只是回话,还能真的替你干活——读写服务器上的文件、操作网页、查代码仓库、定时做事。这一切数据都存在你自己家里,不经过任何第三方。

它和直接用 ChatGPT 有什么不同

四个「自己的」。

自己的账本

所有聊天、文件、总结都存在你服务器上的一个文件里。备份就是复制这个文件,搬家就是带走这个文件。账号说停就停,数据也是你的。

自己的记忆

它记得住你。#smalltalk 频道里的每条碎念都会被沉淀成卡片;历史对话用 search_history 随时翻出来。越用越懂你,而不是每次从零开始。

自己的自动化

内置一套「规则引擎」(按你写好的规矩自动做事):你安静一小时,它自动把想法总结成卡片并推送到工作频道——不需要你记得去总结。

自己的门

账号密码登录,每人默认只能看到自己的对话;要共享,由你主动邀请。执行敏感操作(删文件、跑命令)前会先来问你批准。

按真实的一天看功能

你的一天,它如何接住。

💬 对话与多端

手机、电脑同时登录,看到完全一样的进度;网页可以「添加到主屏幕」,像原生 App 一样用。

#️⃣ 频道

像 Discord 一样建频道;输入框敲 # 就能把别的频道「@」进来;agent 还能跨频道投递消息(channel_post)。

🎙 语音

按住说话,松手自动转成文字消息;中文、英文、德文可选,转写失败自动重试,不影响聊天主功能。

⚙️ 规则引擎

静默倒计时、自动总结、跨频道推送——规矩写在一个文件里,改完立即生效,还能在日程面板里暂停和编辑。

🔒 私有隔离

每人默认只看到自己的对话和频道;共享群组由创建者主动勾选成员,或发放单场对话的邀请链接。

🔍 历史检索

search_history 让 agent 能翻过去的聊天档案:当前频道、全部频道、指定条数范围都行,查询优先、绝不凭空猜。

第二部分 · 代码实现

代码是怎么组织的。

整个项目的代码放在一个「仓库」(repo,一个项目全部代码和历史档案的柜子,托管在 GitHub 上)里。把它想象成一栋楼:你在前台看到的界面、后台干活的程序、质检的测试、说明文档,各占一层。

技术栈,只有三样

整套系统只用三件工具。

Node.js — 车间的电力

后端程序用它运行。整个服务就是一个「进程」(process,正在运行中的一份程序),启动、重启、看日志都围着它转。

SQLite — 一本账

数据库(database,有组织地存数据的地方)不用装一整套软件,就是服务器上的一个文件。整站数据——聊天、频道、账号、规则——都在里面。

Preact + htm — 前台货架

前端界面用它搭建。有个难得的特点:没有「构建」这道工序(构建=把人写的代码加工包装成可运行版本的额外步骤)。改完代码,刷新页面就生效。

第三部分 · 架构设计

整体是怎么设计的。

架构(architecture,系统的整体布局与分工方式)可以用一句话概括:一个进程,一本账,先记账再广播。下面三张图,分别看分层布局、一条消息怎么走完、以及为什么这么设计。

为什么这么设计

三个关键决定,各有一个代价。

决定一:单进程 + 单账本

全站只有一个正在运行的程序、一个数据库文件,不搞分布式(多台机器分摊)。

极简可靠:备份=复制一个文件;数据永远不会出现「两个版本打架」。 同一台服务器同时只能跑一个 Picord——对个人自托管,这正好够用。

决定二:先落账,再广播

界面显示的每个字,都是账本里已经提交的内容;断电、崩溃、刷新页面都不丢。

多设备永远一致;崩溃后从上次进度继续,不重复、不丢失。 内容上屏最多慢 90 毫秒(批量打包的等待)——人感觉不到。

决定三:功能即插件

频道、语音、规则引擎、历史检索……全都是「扩展」(extension,按统一接口挂上去的功能模块)。

加功能像往墙上挂画,不动承重墙;拆掉也不伤主结构。 插件必须遵守管家的接口规矩——好在有文档、示例和测试兜底。
第四部分 · 你的 fork

上游给了什么,你改了什么。

「fork」(分叉)是把别人的项目复制一份成自己的,从此各走各路。上游(原项目 TannerMidd/pi-pocket)打好了地基:Pi Durable 管家、扩展机制、会话与工具、基础界面。你的 Picord 在地基上装修出了自己的房子——下面是五轮主要演进,每一轮都始于真实使用的痛点。

  • 2026-11-21 · 独立建仓 从上游分叉;界面全面中文化;上线 Discord 风格频道与语音转文字;去掉「外部聊天平台中继」(把消息转发到微信类平台的旧功能,与自托管定位冲突)。
  • 2026-11-24 ~ 25 · 会自己干活的规矩 规则引擎上线:静默倒计时、自动总结、跨频道推送;账号密码登录取代一次性链接;确立 Picord 独立品牌。
  • 2026-11-26 · 吸收上游新版 + 内部整理 合并上游 v0.30.1 的新能力;把大文件拆成职责清晰的模块(像把杂物间分成三个分工明确的工位);手机语音体验升级(按住说话、屏幕常亮)。
  • 2026-11-27 · 隐私隔离 + 仓库瘦身 默认每人只看自己的对话;删掉上游遗留的桌面安装包等用不上的部分;全量测试接入 CI(提交后自动跑测试的防线)。
  • 持续 · 文档与可视化 README、双语文档站、本页导读、中文架构页——让人(包括未来的你)随时能看懂全貌。
